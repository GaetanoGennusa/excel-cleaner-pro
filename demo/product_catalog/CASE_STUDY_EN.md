# Product Catalog Cleanup with an Auditable Handover

Synthetic portfolio demonstration. No client engagement, testimonial or measured business outcome is represented.

Development disclosure: Excel Cleaner Pro and these portfolio materials were created with assistance from Claude (Anthropic) and Codex (OpenAI), following the project owner's instructions. AI assistance covered code, UI, tests and documentation. Uploaded files are processed by explicit Python rules, without calls to AI models at runtime.

## The input

A deliberately messy CSV contains 200 records and eight columns: SKU, name, category, EUR price, availability, update date, supplier code and notes. It represents 190 invented products, six exact duplicate records and four additional records that differ only in name spacing or case.

## The agreed work

Normalize whitespace; apply title case to product names and categories; parse prices and stock using explicit Italian number conventions; normalize dates using a chosen day/month/year format. Preserve identifiers and missing values. Remove exact source duplicates only after confirmation.

## The demonstrated result

The output contains 194 records. All 190 SKUs remain present. Six exact copies are removed, while four similar pairs remain available for a business decision. Seven missing cells remain missing. Three malformed prices, one textual availability value and two invalid dates are retained and reported.

SKU `000001` remains text, its synthetic price `€ 1.234,56` becomes the number `1234.56`, and `01/02/2026` becomes the ISO text `2026-02-01`. The export includes cleaned data, source/conversion issues, a per-cell change log and settings with a UTC timestamp.

## Why this handover is useful

The recipient can inspect the output and trace changes back to source row positions. Unresolved values and similar records remain visible instead of being guessed or silently deleted. This is a demonstrated workflow, not evidence of commercial accuracy, savings or guaranteed import compatibility.

## Boundaries

The application does not validate product identity, correct prices or stock, merge variants, calculate taxes or upload products to an online store. The output schema and unresolved fields require review before any import. Text-case changes must be agreed on real names and brands. The project remains subject to manual acceptance for a particular delivery.

The downloadable CSVs and report are generated by the Python engine. Screenshots, a separate browser-downloaded report and the silent recording are produced by the real app verification workflow. The portfolio page presents precomputed samples; it does not process new files.

Local processing does not mean RAM-only processing: XLSX generation uses temporary local XML files, removed after successful export; crashes may leave remnants.
